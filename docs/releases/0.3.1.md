# 0.3.1：紧凑触控输入高度一致性

## 可复现问题

在本库0.3.0主题、iOS默认字号下测量实际 RenderBox：裸 TextField 42点、静态前缀图标44点、后缀 IconButton/双图标48点，普通 InputDecorator 42点，IanvsTextField/Select 44点。此前只测 Ianvs 封装的尺寸范围，未覆盖原生输入装饰组合的一致性。

原因是输入主题未设置最小高度，封装单独使用 controlHeight=44，而 padded 图标按钮需要48点。只设置整体 constraints 仍不足以保护带 helper/error 的输入表面，因为 Flutter 会为辅助文字分配整体高度的一部分。

## 修复与接入

紧凑触控输入主题现在设置48点最小高度、前后图标48×48最小区域，并使用 `isDense: false` 保留 Flutter 的48点输入表面下限。显式10点垂直内边距、16点正文、13点堆叠标签/4点标签间距不变。IanvsTextField、IanvsSelect 和步进器沿用主题输入约束；显式 decoration constraints 继续优先，大字号和多行可以自然增长。

调用仍为 `IanvsTheme.build(density: IanvsDensity.touch, touchVisualDensity: IanvsTouchVisualDensity.compact, platform: TargetPlatform.iOS, ...)`。controlHeight=44保留为按钮外观尺寸，宿主输入不应再用它覆盖主题约束；自定义 InputDecorator 应使用 `applyDefaults(theme.inputDecorationTheme)`。

Flutter 原生 DropdownMenu 自带箭头四周4点边距，因此默认56点才能保留内部48点 padded 按钮。本次解除其旧高度裁剪并为箭头留足宽度。这个框架组件是明确例外；IanvsSelect 和普通 InputDecorator 选择框均保持48点。没有为统一外观裁剪图标触达区。

## 验证

- 新增7项测试，修复前装饰组合回归失败，修复后通过；测量真实 RenderBox 及 InputDecorator 输入表面。
- 深浅色 × 1/2/3倍文字：普通输入、前缀、后缀、双图标、InputDecorator、IanvsTextField/Select 高度一致，1倍为48点，大字号继续增长。
- helper/error 输入表面保持至少48点，辅助文字在表面之外增加高度；图标实际触达尺寸和点击回调、多行增长、宿主显式72点约束通过。
- `flutter analyze` 无问题；全部库121项、展厅70项，共191项测试通过。
- Web/macOS release 构建通过；Dart 格式和 diff 检查通过。

本次仅只读参考 Trail 测试和自定义选择组件，没有修改其工作区或操作桌面、Simulator、真机。宿主原生界面与业务流程由 Trail 任务继续验证。
